# Working Note: Resolving the W(3) / Stability-Bound Tension

**Date:** 2026-08-14  
**Status:** Draft options — no option is yet selected as canonical.

---

## 1. Statement of the Conflict

Two statements coexist in the repository cluster:

1. Phenomenological / galactic / muonic formulae use the locked anchor
   \[
   W_\star \approx 0.08
   \]

2. The M2 engineering table (and the evaluator assert that previously existed) uses
   \[
   W(n) = 0.08 \, e^{0.23(n-1)}
   \quad\Rightarrow\quad
   W(3) \approx 0.1267,\quad W(4) \approx 0.1595
   \]

3. An earlier stability argument asserted a ghost-free bound
   \[
   W(n) < 0.125
   \]

Statements 2 and 3 are mutually inconsistent. Statement 1 is the value that actually appears in the kill-gate expressions.

---

## 2. Origin of the Numbers

- \(W_\star = 0.08\) emerged as a recurring phenomenological consistency point (rotation curves, muonic order-of-magnitude, lensing amplification).
- The exponential M2 form was introduced to give the fractal recursion a depth-dependent coupling; the exponent 0.23 was motivated by a Hausdorff-dimension estimate of the 0.45 Sierpinski lattice.
- The numerical table was generated by simply evaluating the exponential at integer n; it was never re-derived from a dispersion relation that enforces the 0.125 bound.

---

## 3. Concrete Resolution Options

### Option A — Keep W_star = 0.08, demote M2 to a pure geometry factor

- Treat the exponential as a relative LDOS enhancement factor \(f(n)\), not as a renormalisation of the gravitational Ware constant.
- All gravitational / muonic / lensing formulae continue to use \(W_\star = 0.08\).
- Engineering force ratios become
  \[
  \Delta F(n) \propto W_\star \cdot f(n) \cdot \text{(geometric integral)}
  \]
  with \(f(3)=1\) by definition.
- Ghost-free bound is automatically satisfied because the gravitational coupling never exceeds 0.08.

**Advantage:** Zero change to existing kill-gate numerics.  
**Cost:** Requires rewriting the engineering language that currently multiplies W(n) directly into \(T_{\mu\nu}^{\rm info}\).

### Option B — Raise or abandon the 0.125 bound

- Accept the tabulated M2 values as the physical coupling at each recursion depth.
- Re-derive the dispersion relation and show that the theory remains ghost-free up to at least W ≈ 0.16 (or identify a new critical value).
- Update every galactic / muonic formula to decide whether it should use W_star or W(n=3).

**Advantage:** Preserves the existing M2 table.  
**Cost:** Requires a new stability calculation; may force a refit of SPARC / lensing numbers.

### Option C — Re-fit the exponent

- Keep the bound W < 0.125 and the functional form \(W(n)=W_\star e^{\xi(n-1)}\).
- Solve for the largest ξ such that W(4) < 0.125:
  \[
  0.08\, e^{3\xi} < 0.125 \quad\Rightarrow\quad \xi < \frac13\ln(1.5625) \approx 0.1487
  \]
- Replace 0.23 by a value ≤ 0.1487 (or by a value derived from a corrected spectral calculation).

**Advantage:** Restores internal consistency while keeping an exponential.  
**Cost:** Breaks the previous link to D ≈ 0.868; requires justification of the new ξ.

---

## 4. Recommendation (Provisional)

Adopt **Option A** as the default working hypothesis for the next development cycle:

- Lock \(W_\star = 0.08\) for all gravitational and spectroscopic expressions.
- Interpret the M2 exponential strictly as a relative geometric / LDOS enhancement that multiplies only the engineering force integral, not the fundamental coupling that appears in the Einstein equation.
- Record the choice in Math.md and in the Symbol Registry of the synthesis repository.

A final decision should be made only after a dedicated stability analysis (Option B) or a first-principles spectral derivation of ξ (Option C) is completed.

---

## 5. Immediate Code Consequence

The evaluator in `stress-tensor-modification` already defaults to `model="star"` (constant 0.08) and emits a warning if `model="M2"` is requested. The kill-gate script uses only \(W_\star\). No further code change is required to implement Option A; only documentation and downstream engineering language need to be aligned.
